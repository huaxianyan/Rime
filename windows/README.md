# 小狼毫自动任务

用于管理小狼毫的自动同步和自动重新部署。面向 Windows 10 22H2／Windows 11 的 x64 设备，使用系统包含的 .NET Framework 4.8，无需安装 PowerShell 7 或新版 .NET 运行时。

首次 Release 尚未发布。本地构建与打包方式见下文。

## 安装与使用

1. 从 [GitHub Releases](https://github.com/huaxianyan/Rime/releases) 下载 Windows x64 压缩包并解压。
2. 打开 `RimeAutomation.exe`，分别选择自动同步与自动重新部署的开关和执行时机。
3. 点击「安装并保存」，确认操作。以后从开始菜单打开「小狼毫自动任务」。

程序会安装到当前用户的固定目录，并添加开始菜单入口，无需选择或记住路径。仅为当前用户创建计划，无需管理员权限或账户密码。安装前可以使用「立即同步」或「立即重新部署」，手动操作也会实际调用小狼毫。

自动同步默认开启，自动重新部署默认关闭，首次设置的每日执行时间为 20:00。首次打开只是预选，确认保存后才会创建计划。

两个功能各自设置开关和每日执行时间，仅保留定时执行，不提供登录或锁屏触发。

**到达计划时间时，即使电脑处于锁屏状态，也照常执行。** 锁屏仍属于已登录状态，无需额外开关，锁屏动作本身也不触发执行。

睡眠、休眠、关机和退出登录不等于锁屏，这些状态下无法按当前方式执行。错过定时时间后，Windows 会在条件允许时补执行，程序不主动唤醒电脑。

保存后可以关闭窗口，程序不常驻后台。以后从开始菜单打开「小狼毫自动任务」即可，主界面不展示安装路径。

### 修改与停用

再次打开程序会读取实际任务设置。修改后点击「保存设置」，原任务随之更新。关闭某个功能会停用对应计划，并保留其触发设置，另一项功能保持原状。

「立即同步」和「立即重新部署」不受自动开关影响。手动执行在单独进程中完成，关闭设置窗口后仍会继续执行。手动结果显示在当前窗口，重新打开或刷新时显示计划任务的最近执行结果。

### 卸载

1. 在窗口点击「移除所有计划」，确认移除本工具创建的计划。
2. 关闭窗口，等待已开始的操作完成。
3. 按 `Win + R`，输入 `%LOCALAPPDATA%\RimeAutomation`，删除其中的 `RimeAutomation.exe`。目录为空时也可一并删除。
4. 按 `Win + R`，输入 `shell:programs`，删除「小狼毫自动任务」快捷方式。

第一版采用上述手动文件清理方式，不提供自动删除自身的卸载程序。Rime 用户配置和词库保留在原位置。停用或移除计划不会强行终止已开始的操作。

## 两种操作的区别

- **同步：** 调用小狼毫 `/sync`，处理用户词典等同步数据，不等于上传全部配置或完成所有设备间的数据传输。
- **重新部署：** 调用 `/deploy`，使本机方案、配置和词库改动生效，执行期间可能短暂影响输入。

两者独立，不在每次同步后自动追加部署。同步位置、设备标识仍由 Rime 的 `installation.yaml` 管理，本工具不解析或修改该文件。网盘等跨设备同步工具需要另行配置。

使用网盘同步配置时，请在文件下载完成后重新部署。到达设定时间不保证网盘已经完成同步，本版不监控文件变化。

## 升级

### 升级小狼毫

计划指向本工具的固定安装位置，每次执行重新读取小狼毫安装器维护的 `HKLM\SOFTWARE\Rime\Weasel` 中的 `WeaselRoot`，兼顾 32 位和 64 位注册表视图。支持安装器设置的自定义目录，不扫描或猜测旧版本目录。

正常原地升级小狼毫后，无需重新开关、保存设置或重建计划。升级期间暂时找不到程序时，本次执行会失败，计划保留原有开关，后续触发重新检测。没有有效安装信息的便携安装不在支持范围内。

### 升级本工具

关闭原设置窗口，下载并打开新版 EXE，检查读取出的现有设置，再点击「更新程序并保存」。程序更新到原安装位置，创建或更新开始菜单入口，并保存当前选择，任务名称保持不变。

从旧预览版更新时，需要保存一次设置，移除原有登录和锁屏触发。已有每日定时时间会保留。如果旧计划没有定时，界面会预填 20:00，请确认或调整后再保存。这是工具功能调整，不改变小狼毫正常升级时无需重建计划的行为。

下载目录中的程序与安装目录相互独立。确认安装成功并关闭下载的程序后，可以清理下载文件。不要移动安装目录中的程序，否则计划将无法找到它。

## 执行结果与限制

- 同一计划还在执行时，不重复启动第二个实例。
- 本工具的同步、部署和手动操作共用执行锁，另一项操作最多等待 5 分钟，超时会显示本次未完成。
- 小狼毫托盘菜单或其他工具发起的操作不在此锁的管理范围内，发生冲突时请在其他操作完成后重试。
- 「命令已成功完成」表示小狼毫进程返回成功，不是对全部词典、配置和云端传输结果的独立检查。
- 本版没有代码签名证书，Windows 可能显示来源或信誉提示。请核对下载来源及 Release 提供的 SHA-256，谨慎决定是否运行，不建议关闭系统安全功能。

此前通过旧脚本或外部教程创建的任务，需要手动停用或移除。本工具只管理自己创建的当前用户计划，不接管其他任务。

## 开发

源码位于 `windows-automation` 分支的 `windows` 目录。用户发布包只包含 EXE、许可证和说明，不包含脚本、测试程序或本地开发上下文文件。

### 构建与测试

开发需要 Windows 和 .NET SDK，推荐 .NET SDK 8。构建时通过 NuGet 获取 .NET Framework 参考程序集，不要求安装 Visual Studio。开发打包脚本使用 PowerShell 7，这不是用户运行程序的依赖。

在仓库根目录执行：

```powershell
dotnet build windows/RimeAutomation.sln -c Release
& ./windows/RimeAutomation.Tests/bin/Release/net48/RimeAutomation.Tests.exe
```

集成验证需要当前用户已登录的 Windows 桌面会话。测试通过真实任务计划程序调用与生产相同的命令分派和执行代码，只替换外部安装信息来源、小狼毫程序以及任务名称和安装目录。

验证范围包括两个计划的创建、执行、时机修改、停用、重新启用、移除、失败结果，以及保留旧版本目录且无需重建任务即可使用新版本。另有回归用例验证旧登录、锁屏触发在保存后被移除，已有定时时间保留。测试不会锁定开发者的电脑，锁屏期间的实际定时执行需要人工验收。

设置窗口测试会打开临时窗口并点击立即执行，不读取截图。安装验证还会在临时目录创建并读取快捷方式，检查其指向安装后的程序，不修改真实开始菜单。另有安装文件替换的输入输出测试。

测试不操作真实词库或用户已有计划。临时任务和文件在结束时清理。测试使用模拟安装信息，不替代真实小狼毫安装升级的人工验收。

### 打包

```powershell
pwsh -NoProfile -File windows/package.ps1 -RunIntegrationTests
```

输出位于 `artifacts`，包括 Windows x64 ZIP 和 SHA-256 文件。已完成构建与测试后，可使用 `-SkipBuild` 单独打包。未指定 `-RunIntegrationTests` 时，脚本会明确提示本次未运行集成验证。

### 发布

1. 更新 `windows/RimeAutomation/RimeAutomation.csproj` 中的版本和 `windows/RELEASE_NOTES.md`。
2. 在本地交互式 Windows 会话中完成集成验证及实际使用验收。
3. 提交并推送 `windows-automation` 分支，在相应提交上创建 `windows-automation-v<版本>` 标签。
4. 推送标签后，GitHub Actions 构建发布包，并创建 Release 草稿。
5. 检查草稿附件与说明，确认后手动发布，并在配置主分支补充下载入口。

普通分支推送只产生 Actions 构建产物。CI 不运行依赖交互登录身份的计划任务集成验证，发布前的本地验证必须单独完成。标签版本必须与项目版本一致，标签提交必须属于源码分支。

目前仅提供 Windows x64，不提前构建跨平台调度层。其他平台或架构如有需要，再单独实现、验收并发布对应二进制。
